# 工作流 V2 产品复核

本轮检查前后端实施规范、现有代码与 Eric 会议原话，重点是用户能否得到有用结果、是否重复操作、是否能自然继续下一次沟通。结论属于设计复核，交互原型和实现后的用户验证按本文验收。

2026-09-29 的实现走查与易用性改进见 [产品易用性复核](PRODUCT_USABILITY_REVIEW_2026-09-29.md)。本文前半部分保留最初的设计判断，当前工程与使用验证以新复核报告为准。

## 产品判断

方案能承接已诊断的七个问题。第一版的版本、引用、状态和结果回流规则较完整，默认交互仍偏重。用户需要的是一份能用、能纠正、会随着进展更新的记录。批阅是其中的少量关键决定。

优先价值场景是重要且会持续跟进的沟通，例如房仲客户、项目推进、咨询和个人重要事务。一次性会议也应在直接阅读和复制时产生价值。用户觉得某件事值得跟进，才继续走答案回流。

Eric 在 40:58–41:51 与 47:34–49:03 质疑先生成重点再逐条核对的重复，在 44:27–44:36 指出左右来回的问题，在 50:24–50:31 明确提出修改后上面的结果应当变化。这些要求共同指向同一份内容中的就地处理。

## 默认循环

放入材料 → 拿到可读、可复制的记录 → 重要处拍板或改一句 → 有事就跟进 → 补结果 → 同一份记录更新 → 下次从变化和下一步继续。

一份记录的默认页面包含三个区域：

- 重点：完整可用内容，草稿与已采纳逐项标明。
- 需要你拍板：和对应重点关联的小卡片，可以为零，首屏最多五条并显示余量。
- 跟进：已采纳的下一步，结果可以直接在行内补充。

原文和音频按需展开。集中批阅、全部行动和仅已确认输出作为辅助视图。三个区域共用信息与操作状态。

## 七个问题的逐项判断

| 已诊断的问题 | 第一版的承接 | 本轮补强 | 用户侧通过条件 |
| --- | --- | --- | --- |
| 不知道先做什么 | 先看重点，再去待批 | 首页直接添加材料，得到完整记录后再命名、归档 | 第一次进入即可阅读或复制 |
| 不知道批准什么 | 区分确认记录和加入行动 | 卡片写明要决定的事与结果，例如采用新预算 | 用户能说出这一点击会改变什么 |
| 修改后概要还是旧的 | 精确版本、依赖更新与更新状态 | 就地修改对应要点，其余内容保持稳定 | 保存一次，刷新和重开仍是新结果 |
| 待批与行动重复处理 | 同一行动按 ID 去重 | 同一约定只出现一张决策卡，内部保留不同语义对象 | 加入跟进后该意图退出优先队列 |
| 被迫审完全部 | 可以处理部分后退出 | 草稿数与待拍板数分开，复制记录默认包含有标识的草稿 | 确认两条后仍能带走完整记录 |
| 完成后答案没有回来 | 执行与答案分别保存 | 已知问题旁输入后一次保存，多目标和旧答案变化时才展开选择 | 报价保存后同时更新费用要点与问题状态 |
| 下次无法接着用 | 项目概览汇总当前状态 | 回顾突出最近变化与下一步，继续这件事新增下一次沟通 | 无需重读历史就知道现在进展到哪里 |

以上是规则和交互的对应关系。实际通过需要操作记录和用户试用证据。

## 本轮补上的四个产品漏洞

### 完整初稿不能因少量确认而收缩

用户确认一条后，主记录继续显示其他草稿。确认更新标识，修改替换对应版本，仅已确认筛选才收窄内容。主复制入口保留草稿标识、未决问题与覆盖范围，从零次批阅起就可用。

### 少量拍板需要筛选规则

优先队列只容纳影响已采纳信息的变化、阻塞当前下一步的问题、原话约定或直接用于补齐问题的行动建议。每条给出具体原因。普通草稿保留就地确认入口，低置信度和待审核状态本身不足以让用户承担一次决定。

少量展示和少量必要决定是两回事。首屏五条只是显示上限，待拍板的实际数量、用户认为值得处理的比例要在试用中检查。

### 提错和漏掉都要能修

提错了，在要点旁改一下。漏掉了，在已有原文中选中一段并补进重点。保存的是有出处的用户选录原文，后续改写仍保留来源归类。该入口补救用户发现的遗漏，整体提取召回仍通过人工标注样本评估。

### 普通结果一次保存，例外明确选择

点击问题旁的补答案，目标已经确定。行动只有一个相关问题时直接带出上下文，答案填完一次保存。多个可能目标逐项填写或选择。已有答案时明确替代或并存，连同旧答案版本一起提交。

完成行动仍是一键操作。执行备注可以单独保存，实际答案才使问题解决。页面使用已完成、可补报价等具体提示，内部状态通过服务端一致性规则维护。

## 一条用户路径

材料提到预算大约三十万元，搬入时间尚未确定，需要向供应商询价。

1. 上传后立即得到包含预算、时间与费用问题的记录。用户可以直接复制离开。
2. 发现预算应为三十五万元，在原位置改一下并保存。其他重点保留。
3. 想跟进费用，点击加入跟进。同一建议更新为行动。
4. 收到报价后在费用问题旁填入十二万元并保存。费用要点更新，问题移出未决列表。
5. 下次继续这件事，先看到当前预算、最新费用和仍待确定的搬入时间。

每一步都有有用的停留点。结果跟随用户实际获得的新信息更新。

## 验证顺序

2026-09-29用户将产品范围确定为 PC。后续原型、截图走查和试用都以桌面及笔记本浏览器为准，检查鼠标操作、键盘焦点、窗口尺寸和多标签页状态。此前手机检查保留为历史记录。

先制作同页流程的可交互原型，再实现核心链路。请五名未参与实现的用户独立完成直接复制、纠错后重开、跟进后补答案三条路径，至少覆盖两名房仲或销售与两名通用场景用户。

记录首次可用结果耗时、切换页面次数、重复判断次数、求助位置和下一次相关沟通的复用情况。普通确认、加入跟进、完成设计为一次点击，修改与单目标答案设计为一次保存，计数排除文字输入与主动查看出处。

另外使用三十份脱敏或授权材料评估提取精确率、召回率、引用支持率和修改量。特别记录预算限定词、主体混淆、重要遗漏和行动建议是否值得执行。流程试用与内容质量分别通过后，再验证任务共享带来的速度和费用变化。

集中展示常用动作、按需展开次要信息参考 [Nielsen Norman Group 的渐进披露原则](https://www.nngroup.com/articles/progressive-disclosure/)。可纠正、可忽略及操作后果清楚参考 [Microsoft 人机交互指南](https://www.microsoft.com/en-us/research/?p=564561)。本方案是这些原则在 Notique 场景的设计应用，效果以实际试用为准。

## 2026-09-29 访问变化与恢复走查

用户写到一半失去访问时，页面保留自己的输入，收起已无权读取的内容。恢复后回到原位置，显示最新记录并核对后再保存。原目标被移除时保留可复制区域，账号变化时清除上一账号输入。原话选录按当前授权重新读取，保存的范围继续关联出处。

截图检查修正了恢复提示的措辞，避免把恢复访问说成一定发生了内容变化。实际操作还发现保存后立即返回项目被旧离开检查拦住，已修正并复测。只读恢复、输入保留、部分组合批阅和无输入时的原文入口均有两个PC尺寸的操作证据。

再次查看Eric会议00:41至00:49的讨论，他质疑已经得到重点后再要求重复确认的价值。现有主路径先给完整记录，用户可以直接复制，仅在发现问题或需要跟进时处理。上述走查使用合成材料，真实内容质量及未参与实现的用户是否理解仍按原验收安排记录。


## 2026-09-29 问题调整走查

已回答的问题在重点中由答案替换，但仍显示对应问题并保留调整问题入口。用户可以把问题问得更准确，逐条选择原答案仍然适用或需要重新确认。全部答案需要重新确认时问题重新待回答，行动完成状态保留，用户可以直接补新答案。原答案同时回答别的问题时，其他关联继续使用。

PC实操覆盖保存后撤回答案、重新待回答后整次撤销、未回答问题修改后直接作答、并发新答案和权限恢复。截图发现修改依据控件的标签不足，已补齐。无答案的窗口缩短，避免留空。1440×900与1366×768分别验证保存入口可见。测试使用合成材料，真实模型内容及独立用户理解继续单独验收。


## 2026-09-29 行动替代的产品复核

一个已完成的询价，换成确认交期，用户需要知道两件事：报价已拿到，交期还要跟进。当前实现把原询价和结果收进已替代的跟进，新确认交期保持待跟进，报价答案继续显示在当前重点。两个事项分别适用时并列保留，完成状态各自维护。

实际PC操作发现旧行动退出当前跟进后，原答案的撤回会被旧行动状态挡住。已修正结果入口，让现有答案继续可以修正或撤回。原完成记录保留，问题根据当前有效答案重新计算。两种PC尺寸已验证退出选择时保留本人适用情况，并在重新核对并发变化后保存。正文滚动，保存入口保持可见。上述证据来自合成资料与实际本地接口，独立试用和真实模型质量仍待验收。


## 2026-09-29 AI助手连接的产品复核

用户先知道授权什么，再去自己的AI助手安装连接。连接页只把有效读取授权标为已授权，AI助手的安装状态以其插件页为准。网页中的采纳与纠错继续更新同一份重点，MCP读取这些现有结果。
