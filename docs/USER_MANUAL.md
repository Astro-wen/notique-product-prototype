# Notique 用户说明书

更新日期：2026 年 8 月 30 日

这份说明写给第一次使用 Notique 的人。使用产品不需要理解代码，也不需要知道 Run、Ledger 或 API 是什么。

完整测试站：[https://notique-evidence-workspace.uclae2e12.chatgpt.site/](https://notique-evidence-workspace.uclae2e12.chatgpt.site/)

本文编写时的公开版本是 **Sites v57**；最终线上版本以站点发布记录为准。本文描述的新版工作区以“项目 → 多次沟通 → 重点、原文、确认和行动”为主线，不再把项目限定为某一行业的客户类型。`AI_DRAFT_CONTEXT` 仍保持关闭（0），所以未经确认的草稿不会影响可信报告。

本轮隔离 Realtor 对照实验因最后一场模型合同无效而未形成可比较的质量分数；请不要把自动化通过或 AI 草稿当作任何行业的准确率承诺。公开站只适合公开、合成或脱敏材料。

## 1. Notique 是做什么的

Notique 是一个个人项目秘书。它把同一项目里分散在录音、逐字稿、手写照片和多次沟通中的信息整理成重点、待确认内容和下一步，需要时又能立即回到原话。项目可以是客户跟进、设计研究、施工协调、团队项目或任何需要长期追踪的主题。

使用时只需要记住这条主线：

```text
建立项目或直接导入第一份来源
→ 录音自动生成逐字稿
→ 系统自动整理本次重点
→ 边读、边听，在右侧对照原话
→ 重要内容可确认、修改或不采纳
→ 从重点直接建立行动
→ 已确认内容进入可信存档
→ 下一次沟通继续积累
```

确认不是进入下一步的强制门槛，但它不会被隐藏：未确认重点会持续显示“需确认”和待确认数量。最重要的规则仍是：**AI 草稿可以先读、先用，但不等于可信事实。只有人确认过的内容，才会进入可信存档和正式报告。**

## 2. 可以添加哪些来源

在当前沟通的“来源”中可以添加：

1. **直接录音**：允许麦克风权限后，可以开始、暂停、继续、结束、试听、重录或保存。
2. **上传已有录音**：选择电脑、手机或外接录音笔中的 MP3、M4A、WAV、WebM、MP4、MPEG 或 MPGA 文件。录音笔通过 USB-C 导入手机只是一个可选方式，不是使用 Notique 的前提。
3. **Transcript 或文字**：上传 TXT、VTT、SRT 或 JSON，也可粘贴补充文字。
4. **手写笔记照片**：从相册选择，或在 iPhone 上使用“拍手写笔记”。JPG、PNG 和 WebP 可直接上传；HEIC/HEIF/HIF 会在当前浏览器能解码时尽力转成 JPEG。
5. **PDF**：当前工作区还没有可靠的 PDF 页面文本提取路径。请把需要分析的页面导出为照片或文字，不要把 PDF 文件的存在当作已读取。

当前单个录音上限是 **100 MB**。上传时页面会显示文件名、已传字节和进度条；多份录音都会保留各自的文件名，底部播放器也会标明当前正在播放哪一份。文件过大或网络中断时，页面会明确报错，不会假装已上传。

录音保存后会先生成带说话人和时间点的逐字稿。逐字稿完成以前，系统不会跳过它、直接对声音猜测事实。HEIC 转换是浏览器端的尽力处理，尚未在实体 iPhone/Safari 上完成全流程验证；转换失败时请改用拍照入口或导出为 JPG。

### 录音建议

1. 尽量让说话人靠近麦克风。
2. 避免同时讲话、强背景音乐和持续噪音。
3. 测试前确认浏览器已经允许麦克风。
4. 重要项目材料先脱敏；当前公开测试站不是正式的数据保险箱。
5. 超过 100 MB 时，先在本地压缩或分成有明确边界的独立沟通，不要随意剪掉影响语义的前后文。

## 3. 第一次使用：完整流程

### 第 1 步：选择或新建项目

项目代表一个需要持续整理的主题，不限行业。

1. 打开测试站。
2. 从顶部“当前项目”选择已有项目，或点击“新建项目”，只填写项目名称即可开始。
3. 如果工作区还没有项目，也可以直接录音或导入第一份来源，系统会建立默认项目和第一次沟通。
4. 浏览器会记住最近打开的项目和沟通位置；原始来源和确认结果仍从服务器读取。

### 第 2 步：选择或添加一次沟通

一次沟通可以是一场会议、一次电话、一次现场拜访或一组属于同一时点的材料。

1. 桌面端的沟通列表在左侧；手机端收在顶部选择器中。
2. 选择已有沟通，或点击沟通列表旁的添加按钮新建一次。
3. 上传前确认顶部的当前项目和当前沟通，避免把来源放到错误位置。

### 第 3 步：在“来源”添加录音、文字或照片

打开当前沟通的“来源”，选择“上传录音”、“上传 Transcript”、“直接录音”或“拍手写笔记”。上传时会显示文件名和真实进度；传输完成后会自动保存并继续整理。网络中断时页面会保留材料状态并给出恢复入口，不需要理解或操作任何底层上传机制。完成后，该来源会直接出现在当前沟通下。

手写照片可以在第一次导入时一起添加，也可以在阅读重点时从右栏补充；它不会阻塞录音逐字稿先进入工作区。

### 第 4 步：让系统自动整理

上传或导入代表你希望处理这份来源。照片、文字完成上传后会尝试自动启动；录音一定等最终逐字稿完成后再启动。不需要再点一次分析按钮，也不需要停在等待状态卡：逐字稿或摘要已可用时，可以在同一工作区先开始阅读。

系统会依次显示：

1. 等待后台启动
2. 准备材料与上下文
3. 识别事实
4. 查漏纠错
5. 必要时加强复核
6. 写入草稿和状态

页面刷新不会创建第二个付费任务。已经创建的后台任务会按原任务恢复检查；只有自动启动失败、会话状态无法保存或原任务失败时，页面才会提供“重新启动分析”或“重新处理”。**关闭页面前，请先确认新沟通已经出现“正在启动分析”或后续状态；尚未启动的任务不保证关页后自动接力。**

### 第 5 步：在“本次重点”边读、边听、边处理

当前沟通顶部只保留四个主入口：**本次重点 / 来源 / 待确认 ┊ 整个项目**。前三个属于当前沟通，“整个项目”直接进入项目概览。

“本次重点”是主工作区：

1. **重点**：先读 AI 整理的本次重点。每条都带支持原话，但“能定位原话”不等于语义已核对。
2. **主题**：按沟通主题快速回到相关原话。
3. **发言人**：查看 Speaker 1、Speaker 2 等说话人的片段。这是识别结果，仍应结合原音确认身份。
4. **逐字稿**：在易读逐字稿和原始逐字稿之间切换，并可搜索原话、筛选发言人或只看重点来源。正式证据、时间点和音频播放以原始逐字稿为准。

点击左侧任意一条重点，右栏会保持当前阅读位置，同时显示：

- 对应的原句、说话人和时间点
- 从该时间点播放录音，或展开更多上下文
- 该重点是“需确认”“已确认”“未采纳”还是“已处理”
- 可用时直接“确认 / 不采纳 / 修改”
- 从这条重点和它的原文直接建立行动
- 已关联的手写照片，或“添加手写笔记”入口

如果该记录还需要补证据，或涉及与旧记录的关系，右栏会禁用一键确认，需要打开详情后再决定。手机端用“阅读 / 处理”切换同一组内容，不会把右栏盖在原文上。

从重点建立的行动会自动带上对应的原文段落，但它仍先进入待确认层；确认后才成为正式行动。系统最多先带入 8 段原文，来源更多时可以在弹窗里调整。只有“下一步”类重点会预填行动文字；预算、偏好等事实只作为依据展示，必须由你明确写出要做什么，避免把事实误存成行动。提交后仍停留在当前工作区，不会自动开启连续核对或把你带到别的页面。如果本次事实识别仍在后台进行，行动可以先保存，但确认、修改和不采纳会等分析结束后再开放，避免打断同一任务。

### 第 6 步：按需确认，状态始终可见

确认是可选的：你可以先阅读摘要、补充手写照片、建立行动或切换到下一次沟通，不需要为了继续使用而一次清空全部待确认内容。

但未确认内容不会被当作已确认：顶部“待确认”、右栏“待确认”和每条重点的状态会持续显示数量与可信状态。金额、日期、责任人、矛盾、低置信内容和候选关系应优先处理。

可以在重点右栏快速处理，也可以打开“待确认”在同一工作台逐条处理。每条记录都要做一个明确决定：

1. **确认**：原意、类型和证据都正确。
2. **修改**：事实大致存在，但表达、范围或证据需要调整。
3. **不采纳**：错误、重复、无关或证据不足。
4. **Occurrence 判断**：只是再次提到、本次有新变化，或者不采纳。

有前后关系时，页面会同时显示新旧两条原文和确认后的影响。必须先接受或拒绝这个关系，才能确认当前记录。

在连续核验中，保存后会打开下一条，不需要回到列表。快捷键为 `Enter` 确认、`E` 修改、`X` 不采纳、`J/K` 下一条/上一条；在文本框中输入时，这些键不会误触裁决。

### 需要更多上下文时

记录详情中的原始证据默认展示：

- 放大的目标句
- 精确高亮的目标短语
- 前两段和后两段上下文
- 说话人和时间点
- 有音频时，从目标时间前约 3 秒开始播放

如果这些内容仍不足以判断，请标记“上下文不足”，再修改或拒绝。不要因为按钮催促而确认。

### 第 7 步：继续下一次沟通

即使本次还有未核验草稿，也可以从左侧沟通列表或手机顶部选择下一次沟通，再添加新来源。默认情况下，后一次分析只继承可信记忆。双层记忆灰度开关开启时，旧草稿也只能作为明显标记的理解线索，不能直接改变可信结果。为新沟通添加来源后，请先看到“正在启动分析”或后续状态再离开页面。

### 第 8 步：查看“整个项目”

点击“整个项目”会直接进入项目概览，不需要经过额外中转页。如果第一次的工作场景还没确认，同一入口会先显示一次上下文确认，不会打开空白中转页。项目列表把 AI 草稿与已确认记录放在同一处，每条明确标注状态；可以按类型筛选，也可开启“只看已确认”。计数为 0 的分区不会制造空页。

项目概览可包括：

1. **事项概况**：项目现在是什么状态。
2. **时间线**：每次沟通在什么时候发生了什么变化。
3. **决定**：已经确认的决定及其证据。
4. **偏好**：当前偏好、条件、决策人、首次出现、最近确认和历史变化。
5. **问题**：仍需确认的问题。
6. **风险**：仍有效的矛盾、阻塞和风险。
7. **下次沟通清单**：下次最值得问什么、确认什么。
8. **下次沟通速览**：进入下一次沟通前的一页摘要。
9. **项目进展**：把 AI 当前理解和“仅已确认”的可信记忆分层显示，不混成一种可信状态。
10. **下一步行动**：查看 AI 建议；确认后可成为正式行动，完成时保留一条人工完成记录。

正式报告只使用已确认内容。证据不足的位置会留空，不会为了看起来完整而编造。第一批来源处理后，项目可能会请你确认一次工作场景，用于跨沟通比较和项目报告；当前重点、逐字稿和逐条核验可以先使用。

### 项目删除、恢复和永久删除

1. 在“当前项目”旁点击“项目菜单”。
2. 选择“移到回收站”。确认框会先显示沟通、来源和待确认数量。
3. 要恢复时，从同一菜单进入“回收站”，点击“恢复并打开”。
4. 要永久删除时，必须输入完整项目名称。永久删除无法撤销。

如果项目还有转写或分析任务在运行，系统会禁止删除并说明原因。永久删除会先清理文件，再删除项目记录；清理失败时项目仍留在回收站，可安全重试。

## 4. 返回、刷新和页面恢复

本轮以后，页面地址会记录当前位置。

1. 从时间线打开证据，左上角应显示“返回时间线”。
2. 从 AI 初稿打开记录，应返回 AI 初稿原位置。
3. 从待确认列表打开记录，应返回同一列表和原来位置。
4. 直接打开一个深层链接、但没有来源时，返回所属沟通。
5. 浏览器返回按钮应与页面箭头一致。
6. 刷新后应恢复项目、沟通、页面、当前记录和项目概览栏目。

历史的 Sites v18 验收曾验证上述只读路径。从时间线打开一条已确认记录时，页面会显示“返回时间线”，不会出现无关的连续审核队列；页面箭头和浏览器返回都能回到时间线。从项目概览返回也会回到项目工作区。直接刷新深层记录时，服务器状态通常会在约 2 至 3 秒内恢复，随后重新显示只读状态和正确的返回标签。这是历史验收记录，不代表本轮未发布构建已通过同样的线上走查。

如果返回位置仍不正确，请记下“从哪里进入、点了哪一条、返回到了哪里”，并保留当时页面地址。

## 5. 常见状态和应该做什么

| 页面状态 | 意思 | 用户应该做什么 |
|---|---|---|
| 等待来源 | 当前沟通还没有可处理内容 | 在“来源”录音、导入录音、上传 Transcript 或添加照片 |
| 正在上传 | 文件正在传入当前沟通 | 查看文件名、已传字节和进度条；不要重复选择同一文件 |
| 正在转写 | 录音正在生成带说话人和时间点的逐字稿 | 可查看分段进度；不要重复上传 |
| 正在启动分析 | 来源已就绪，系统正在自动建立原任务 | 不需要再点按钮；等待状态前进 |
| 等待后台启动 | 同一任务已经创建，等待后台领取 | 先等待；页面会继续检查原任务，不要重复提交 |
| 正在识别事实 | 第一轮正在盘点重点和原始证据 | 等待，不要重复提交 |
| 正在查漏纠错 | 第二轮正在检查漏项、重复和前后关系 | 等待，不要重复提交 |
| 需要加强复核 | 确定性检查发现风险，正在追加一次复核 | 等待；这不是失败 |
| 等待场景确认 | 第一批来源已处理，项目上下文还未确认 | 可先阅读重点和原文；生成正式项目报告前选择或填写工作场景 |
| 重点已就绪 | AI 草稿可阅读 | 点击重点，在右栏对照原话、播放录音或建立行动 |
| 需确认 | 内容已提取，但还不是可信事实 | 可以稍后处理；金额、日期、责任人、矛盾和低置信内容应优先核验 |
| 部分已核对 | 一部分已进入可信存档，仍有草稿 | 可继续核验、查看整个项目，或进入下一次沟通 |
| 已确认 | 当前内容已经人工核验 | 可在“整个项目”查看可信存档、时间线和行动 |
| 需要处理 | 有上传、转写、自动启动、停滞或来源问题 | 按错误卡片提供的“重试 / 重新转写 / 重新启动分析 / 检查状态”处理 |

## 6. 出错时怎样恢复

### 6.1 “仍在后台运行”

点击“检查状态”。这个动作只查询原任务，不会创建新 Run，也不会重复付费。

### 6.2 “处理失败”

先阅读错误原因：

- 网络或临时服务错误：使用“重新处理”。
- 转写失败：录音仍然保留，使用“重新转写”。
- 输出为空：先检查来源是否有可识别的文字，再决定是否重新处理。
- 原始证据不完整：查看缺少哪份来源，不要强行确认。

### 6.3 页面看起来卡住

1. 先刷新，系统会从服务器恢复真实阶段。
2. 如果仍显示运行中，点击“检查状态”，不要再次上传或重复处理。
3. 超过合理时间仍没有变化时，到“高级工具 → Run Debug”查看阶段；提交问题时保留 Request ID，但不要复制密钥或客户隐私。

### 6.4 麦克风不可用

1. 检查浏览器地址栏的麦克风权限。
2. 关闭占用麦克风的其他应用。
3. 如果浏览器不支持直接录音，使用“上传已有录音”。

## 7. 每个功能在哪里

| 功能 | 页面位置 |
|---|---|
| 项目选择、新建项目 | 项目工作区顶部的“当前项目” |
| 沟通列表、新增沟通 | 桌面端左侧；手机端顶部选择器 |
| 直接录音、导入录音、上传文字 | 当前沟通 → 来源 |
| iPhone 拍照或选择手写笔记 | 当前沟通 → 来源；或点选重点后的右栏 |
| 上传文件名、字节数和进度 | 当前沟通四个主入口下方 |
| AI 摘要、主题、发言人和逐字稿 | 当前沟通 → 本次重点 |

## 8. 隐私和共享 Workspace 边界

当前公开 Sites 是 **MVP 测试环境**，不是正式多租户产品。

1. 测试者可能进入同一个共享 Workspace。
2. 项目数据和模型额度可能由同一测试环境共同使用。
3. 不要上传身份证件、账号密码、医疗记录、未脱敏合同或真实人员/项目敏感材料。
4. R2 文件存储和 Evidence API 已有项目范围校验，但正式对外使用前仍需完成独立 Workspace、权限和费用隔离验收。
5. 公开许可、合成或脱敏材料最适合当前测试。

## 9. 当前能力边界

1. AI 准确率尚未被证明达到 95%。
2. PDF 没有可靠的页面提取适配器时，不能参与事实识别。
3. 网页端会尽力把 iPhone HEIC/HEIF/HIF 转成 JPEG；若当前浏览器无法解码，会明确提示改用拍照入口或导出为 JPG。该路径尚未在实体 iPhone/Safari 上完成全流程验证。
4. 图片能上传不代表图片事实召回已经合格。
5. 一份录音只能验证一次沟通，不能证明跨沟通的偏好演化。
6. 当前方案没有 CRM、Calendar、Analytics 或正式企业权限后台。
7. 历史的 Sites v18 线上验收只使用了已有记录，没有发起新付费分析；当前构建仍需单独完成一次正式站线上付费 Run 验证。
8. 手机布局已通过样式和自动化检查，但仍需在真实手机浏览器完成一次人工流程。

### 一次真实长录音可以等多久

一段约 21 分钟的公开许可多人会议此前已经在受控 Run 中跑通。以下时间是历史样本记录，不是当前正式站的线上性能结果或速度承诺：

1. 排队不到 0.02 秒。
2. 录音转写约 6 分 52 秒。
3. 双 Agent 和加强复核约 3 分 08 秒。
4. 从开始转写到 AI 初稿完成约 10 分钟。

这只是一次样本，不是速度承诺，但可以帮助判断页面是否真的卡住。长录音处理时请以阶段计时器为准：只要阶段仍在更新，就不要重新上传或重复处理。如果长时间停留在同一阶段且计时不再变化，再使用“检查状态”。

这次测试也说明了一个重要边界：原始逐字稿保留了预先写定的 8/8 个关键事实，但 AI 草稿只抓到其中 6/8，Evidence 安全门之后只留下 4/8。因此测试者仍需阅读草稿、核对前后文，并在漏项时补充重要信息；当前版本不能当作无人检查的自动会议记录。

## 10. 测试后请记录什么

为了让一次使用真正帮助产品改进，请记录：

1. 上传和转写是否成功。
2. 等待后台启动、转写、识别事实、查漏纠错和总时间。
3. AI 初稿抓对了多少条、漏了多少条。
4. 人工确认、修改、拒绝和补充各多少条。
5. 原始证据的前后文是否足够判断。
6. 返回和刷新是否回到正确位置。
7. 时间线是否真的看出“什么时候发生了什么变化”。
8. 完成全部核对花了多久。
