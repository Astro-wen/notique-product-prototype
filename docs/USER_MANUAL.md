# Notique 用户说明书

更新日期：2026 年 8 月 16 日

这份说明写给第一次使用 Notique 的人。使用产品不需要理解代码，也不需要知道 Run、Ledger 或 API 是什么。

完整测试站：[https://notique-evidence-workspace.uclae2e12.chatgpt.site/](https://notique-evidence-workspace.uclae2e12.chatgpt.site/)

当前公开版本是 **Sites v23**。买方客户项目、可选核对、客户进展、下一步行动、三层 Transcript 阅读和项目回收站已经上线。`AI_DRAFT_CONTEXT` 仍保持关闭（0），所以未经核对的草稿不会影响可信报告。

本轮隔离 Realtor 对照实验因最后一场模型合同无效而未形成可比较的质量分数；请不要把自动化通过或 AI 草稿当作房地产准确率承诺。公开站只适合公开、合成或脱敏材料。

## 1. Notique 是做什么的

Notique 当前主要帮助买方经纪人管理同一位买家的多次沟通：持续追踪预算、区域、偏好、房源反馈、未决问题和下一步，而不只是做一份会议摘要。

每一次沟通都会经历同一个循环：

```text
添加材料
→ 生成逐字稿（如果是录音）
→ AI 生成初稿
→ AI 摘要与易读稿立即可用
→ 人优先核对重要事实和前后关系，也可以稍后继续
→ 已确认内容进入可信记忆
→ 下一次沟通继续追踪客户变化
→ 生成客户进展、下一步、时间线和会前速览
```

最重要的规则只有一条：**AI 初稿可以使用，但不等于可信事实。只有人确认过的内容，才会进入正式报告。**

## 2. 可以上传自己的音频吗

可以。

有两种方法：

1. **直接录音**：在材料页点击“直接录音”，允许麦克风权限，然后开始、暂停、继续、结束、试听、重录或保存。
2. **上传已有录音**：选择电脑或手机里的 MP3、M4A、WAV、WebM、MP4、MPEG 或 MPGA 文件。

当前单个录音上限是 **100 MB**。文件太大时，页面会在上传前明确提示，不会传到一半才失败。

录音保存后会先生成带说话人和时间点的逐字稿。逐字稿完成以前，系统不会跳过它、直接对声音猜测事实。

### 录音建议

1. 尽量让说话人靠近麦克风。
2. 避免同时讲话、强背景音乐和持续噪音。
3. 测试前确认浏览器已经允许麦克风。
4. 重要客户材料先脱敏；当前公开测试站不是正式的客户数据保险箱。
5. 超过 100 MB 时，先在本地压缩或分成有明确边界的独立沟通，不要随意剪掉影响语义的前后文。

## 3. 第一次使用：完整流程

### 第 1 步：选择或建立项目

新项目代表同一位买家的购房旅程。

1. 打开测试站。
2. 从当前项目中选择已有项目，或点击“新建买方客户项目”。新项目会直接设为买方场景，不再要求 AI 猜测。
3. 系统会记住最近打开的项目和沟通。浏览器只保存两个位置 ID，真实材料和审核结果仍从服务器读取。

### 第 2 步：添加一次沟通

一次沟通可以是一场会议、一次电话、一次现场拜访或一组属于同一时点的材料。

1. 选择现有沟通，或点击“新增一次沟通”。
2. 确认页面顶部显示的当前项目和当前沟通。
3. 再上传材料，避免把文件放到错误的沟通。

### 第 3 步：添加材料

当前支持：

- Transcript 或文字材料
- 已有录音
- 浏览器直接录音
- JPEG、PNG、WebP 照片
- PDF（保留为材料；如果没有页面文本适配器，系统会明确说明不能参与分析）

录音会先转写。材料准备好后，状态会变成“可以分析”。

### 第 4 步：开始分析

点击一次主按钮“开始分析”。

系统会依次显示：

1. 等待后台启动
2. 准备材料与上下文
3. 识别事实 · `xhigh`
4. 查漏纠错 · `high`
5. 必要时加强复核 · `xhigh`
6. 写入结果

页面刷新不会创建第二个付费任务。下一次沟通也不会自动产生模型费用，仍要由用户点击一次确认。

### 第 4.5 步：怎样看 Transcript

Transcript 里有三个版本，它们的用途不同：

1. **AI 摘要**：先读整场重点。每个重点都带一段真实原话；点击后可以回到对应原始位置，也可以进入相关事实核对。
2. **易读逐字稿**：默认打开。它仍是一份完整逐字稿，只补标点、分段和保守的识别修正。带“需要留意”的段落应点开差异，再听原音频。
3. **原始逐字稿**：声音识别的原始版本，永久保留。正式 Evidence、时间点和音频播放都以它为准。

易读稿或摘要还没完成时，原始逐字稿仍然可以直接阅读，事实识别也不会被它们单独失败所阻断。旧项目可以单独点击“生成 AI 摘要”或“生成易读逐字稿”，不用重新支付事实识别费用。

### 项目删除、恢复和永久删除

1. 在“当前项目”旁点击“项目菜单”。
2. 选择“移到回收站”。确认框会先显示沟通、材料和待核对数量。
3. 要恢复时，从同一菜单进入“回收站”，点击“恢复并打开”。
4. 要永久删除时，必须输入完整项目名称。永久删除无法撤销。

如果项目还有转写或分析任务在运行，系统会禁止删除并说明原因。永久删除会先清理文件，再删除项目记录；清理失败时项目仍留在回收站，可安全重试。

### 第 5 步：确认使用场景（仅旧项目）

新的买方客户项目已经固定场景，不需要这一步。旧项目第一次分析时，系统仍会给出使用场景候选。

请选择最符合实际的一项。这个选择告诉系统需要长期追踪哪些类型的信息，例如预算、条件、责任人、偏好、开放问题和风险。

同一项目通常只确认一次。后续沟通会沿用已经确认的场景。

### 第 6 步：先读 AI 初稿

AI 初稿让用户先判断整场大意，不要求一上来就处理孤立卡片。

1. 重点按原始时间和业务主题显示。
2. 点击重点可打开对应 Claim 和 Evidence。
3. 状态会显示未审核、已确认、已修改或不采纳。
4. 如果漏了重要信息，点击“AI 漏掉了重要信息”，从逐字稿中选择原文并补充。

“初稿基本可用”只是体验反馈，不会自动确认任何事实。

### 第 7 步：连续核对

建议先处理金额、日期、责任人、矛盾、低置信内容和候选关系。其余内容可以稍后核对，不必为了继续下一场而一次清空。

核对时，每条记录都要做一个明确决定：

1. **确认**：原意、类型和证据都正确。
2. **修改**：事实大致存在，但表达、范围或证据需要调整。
3. **不采纳**：错误、重复、无关或证据不足。
4. **Occurrence 判断**：只是再次提到、本次有新变化，或者不采纳。

有前后关系时，页面会同时显示新旧两条原文和确认后的影响。必须先接受或拒绝 Relation，才能确认当前 Claim。

保存后会自动打开下一条，不需要回到列表再点一次。

### 第 8 步：查看 Evidence

Transcript Evidence 默认展示：

- 放大的目标句
- 精确高亮的目标短语
- 前两段和后两段上下文
- 说话人和时间点
- 有音频时，从目标时间前约 3 秒开始播放

如果这些内容仍不足以判断，请标记“上下文不足”，再修改或拒绝。不要因为按钮催促而确认。

### 第 9 步：继续下一次沟通

即使本次还有未核对草稿，也可以选择下一次沟通。系统不会自动开始付费分析。

确认材料正确后，点击一次“开始分析下一次沟通”。默认情况下，后一次分析只继承可信记忆；双层记忆灰度开关开启时，旧草稿也只能作为明显标记的理解线索，不能直接改变可信结果。

### 第 10 步：查看结果

分析完成后可以分别查看 AI 当前理解和可信结果。完整页面包括：

1. **事项概况**：项目现在是什么状态。
2. **时间线**：每次沟通在什么时候发生了什么变化。
3. **决定**：已经确认的决定及其证据。
4. **偏好**：当前偏好、条件、决策人、首次出现、最近确认和历史变化。
5. **问题**：仍需确认的问题。
6. **风险**：仍有效的矛盾、阻塞和风险。
7. **下次沟通清单**：下次最值得问什么、确认什么。
8. **会前速览**：进入下一次沟通前的一页摘要。
9. **客户进展**：把 AI 当前理解和 Verified-only 可信记忆分栏显示，不混成一种可信状态。
10. **下一步行动**：查看 AI 建议；确认后可成为正式行动，完成时保留一条人工完成记录。

报告只使用已确认内容。证据不足的位置会留空，不会为了看起来完整而编造。

## 4. 返回、刷新和页面恢复

本轮以后，页面地址会记录当前位置。

1. 从时间线打开证据，左上角应显示“返回时间线”。
2. 从 AI 初稿打开记录，应返回 AI 初稿原位置。
3. 从审核列表打开记录，应返回同一列表和审核游标。
4. 直接打开一个深层链接、但没有来源时，返回所属沟通。
5. 浏览器返回按钮应与页面箭头一致。
6. 刷新后应恢复项目、沟通、页面、Claim 和报告栏目。

Sites v18 保留并验证了上述只读路径。从时间线打开一条已确认记录时，页面会显示“返回时间线”，不会出现无关的连续审核队列；页面箭头和浏览器返回都能回到时间线。从报告栏目返回也会回到核心工作台。直接刷新深层记录时，服务器状态通常会在约 2 至 3 秒内恢复，随后重新显示只读状态和正确的返回标签。

如果返回位置仍不正确，请记下“从哪里进入、点了哪一条、返回到了哪里”，并保留当时页面地址。

## 5. 常见状态和应该做什么

| 页面状态 | 意思 | 用户应该做什么 |
|---|---|---|
| 等待材料 | 还没有可分析内容 | 上传 Transcript、录音或照片 |
| 正在转写 | 录音正在生成逐字稿 | 保持页面打开或稍后刷新；不要重复上传 |
| 可以分析 | 材料已准备好 | 点击一次“开始分析” |
| 等待后台启动 | 任务已经创建，等待执行者领取 | 先等待；15 秒后系统会唤醒同一个任务 |
| 正在识别事实 | Agent A 正在盘点原子事实 | 等待，不要重复提交 |
| 正在查漏纠错 | Agent B 正在检查 | 等待，不要重复提交 |
| 需要加强复核 | 确定性检查发现风险，正在追加一次复核 | 等待；这不是失败 |
| 等待场景确认 | 第一次分析已完成 | 选择最符合实际的场景 |
| 草稿可用 | AI 初稿已准备好、尚未核对 | 可以先用摘要，核对重要内容，或稍后继续下一次沟通 |
| 部分已核对 | 一部分已进入可信记忆，仍有草稿 | 查看客户进展；继续核对或开始下一次沟通 |
| 可信 | 当前候选都已处理 | 查看可信报告、行动或继续下一次沟通 |
| 需要处理 | 有失败、停滞或材料问题 | 按错误卡片的明确动作处理 |

## 6. 出错时怎样恢复

### 6.1 “仍在后台运行”

点击“检查状态”。这个动作只查询原任务，不会创建新 Run，也不会重复付费。

### 6.2 “处理失败”

先阅读错误原因：

- 网络或临时服务错误：使用“重新处理”。
- 转写失败：录音仍然保留，使用“重新转写”。
- 输出为空：先检查材料是否有可识别的文字，再决定是否重新分析。
- Evidence 不完整：查看缺少哪份材料，不要强行确认。

### 6.3 页面看起来卡住

1. 先刷新，系统会从服务器恢复真实阶段。
2. 如果仍显示运行中，点击“检查状态”，不要再次上传或开始分析。
3. 超过合理时间仍没有变化时，到“高级工具 → Run Debug”查看阶段；提交问题时保留 Request ID，但不要复制密钥或客户隐私。

### 6.4 麦克风不可用

1. 检查浏览器地址栏的麦克风权限。
2. 关闭占用麦克风的其他应用。
3. 如果浏览器不支持直接录音，使用“上传已有录音”。

## 8. 隐私和共享 Workspace 边界

当前公开 Sites 是 **MVP 测试环境**，不是正式多租户产品。

1. 测试者可能进入同一个共享 Workspace。
2. 项目数据和模型额度可能由同一测试环境共同使用。
3. 不要上传身份证件、账号密码、医疗记录、未脱敏合同或真实客户敏感材料。
4. R2 文件存储和 Evidence API 已有项目范围校验，但正式对外使用前仍需完成独立 Workspace、权限和费用隔离验收。
5. 公开许可、合成或脱敏材料最适合当前测试。

## 9. 当前能力边界

1. AI 准确率尚未被证明达到 95%。
2. PDF 没有可靠的页面提取适配器时，不能参与事实识别。
3. HEIC/HEIF 照片尚不支持；请先转成 JPEG、PNG 或 WebP。
4. 图片能上传不代表图片事实召回已经合格。
5. 一份录音只能验证一次沟通，不能证明跨沟通的偏好演化。
6. 当前方案没有 CRM、Calendar、Analytics 或正式企业权限后台。
7. Sites v18 的本轮线上验收使用已有记录，没有发起新付费分析；Summary、易读稿和后台新架构仍需单独完成一次线上付费 Run 验证。
8. 手机布局已通过样式和自动化检查，但仍需在真实手机浏览器完成一次人工流程。

### 一次真实长录音可以等多久

一段约 21 分钟的公开许可多人会议此前已经在受控 Run 中跑通。以下时间是历史样本记录，不是 Sites v18 的线上性能结果或速度承诺：

1. 排队不到 0.02 秒。
2. 录音转写约 6 分 52 秒。
3. 双 Agent 和加强复核约 3 分 08 秒。
4. 从开始转写到 AI 初稿完成约 10 分钟。

这只是一次样本，不是速度承诺，但可以帮助判断页面是否真的卡住。长录音处理时请以阶段计时器为准：只要阶段仍在更新，就不要重新上传或重复点击“开始分析”。如果长时间停留在同一阶段且计时不再变化，再使用“检查状态”。

这次测试也说明了一个重要边界：Transcript 保留了预先写定的 8/8 个关键事实，但 AI 初稿只抓到其中 6/8，Evidence 安全门之后只留下 4/8。因此测试者仍需阅读初稿、核对前后文，并使用“AI 漏掉了重要信息”；当前版本不能当作无人检查的自动会议记录。

## 10. 测试后请记录什么

为了让一次使用真正帮助产品改进，请记录：

1. 上传和转写是否成功。
2. 等待后台启动、转写、Agent A、Agent B 和总时间。
3. AI 初稿抓对了多少条、漏了多少条。
4. 人工确认、修改、拒绝和补充各多少条。
5. Evidence 前后文是否足够判断。
6. 返回和刷新是否回到正确位置。
7. Timeline 是否真的看出“什么时候发生了什么变化”。
8. 完成全部核对花了多久。
